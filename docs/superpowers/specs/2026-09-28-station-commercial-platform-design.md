# 车站商业空间数字化展示平台设计

## 目标

交付一个可在桌面浏览器直接体验的前端 Prototype，串起登录、车站总览、吴川站 1F 互动地图、店铺信息抽屉和店铺详情五个状态。视觉语言采用铁路枢纽与数字孪生的深色技术感，避免普通后台卡片化样式。

## 方案

- **视觉**：石墨黑、蓝灰和低饱和青色作为底色与交互色，铁路红只用于状态强调；细线、网格和 HUD 数据标签让平面图成为空间探索主角。
- **结构**：React + TypeScript + Vite；`App` 只管理路由级状态，页面和交互拆到独立组件；mock 数据放在 `src/data`，字段按照未来 API 响应建模。
- **地图**：原始吴川站规划图放入 public 作为底图，地图上方覆盖 SVG/HTML 热点。地图容器自己实现滚轮缩放、拖动、缩放按钮、适应窗口和重置视图，不引入 GIS。
- **交互**：登录接受任意非空账号密码；点击店铺区域先打开右侧抽屉，详情按钮才进入详情页；返回按钮回到地图并保留选中店铺。
- **扩展**：`Station`、`Floor`、`Shop`、`ShopMedia` 类型预留描述、联系方式、媒体和招商状态字段；楼层选择器保留 B1/1F/2F/3F 的扩展入口。

## 真实素材与已知假设

- 使用用户提供的吴川站一层商业规划图作为真实底图，未裁剪和重绘。
- 目前只有 1F01/1F02/1F03 三个空间，因此热点位置以图面比例标注为百分比坐标。
- 三个店铺预留电量按用户确认的 30KW 计算，合计展示为 90KW；原始表格中的合计 100 不被分配给单店。
- 店铺实体照片、联系人和招商状态显示为空状态“待补充”，不生成虚构照片。

## 组件边界

- `LoginPage`：登录表单与背景空间线稿。
- `StationOverview` / `StationCard`：车站级入口与未来接入占位。
- `StationMap`：地图页布局、顶部导航、空间统计和抽屉编排。
- `MapViewer`：底图、热点、拖动缩放和控件。
- `ShopInfoDrawer`：选中店铺的摘要。
- `ShopDetail`：单店详情、媒体空状态与扩展字段。
- `AppShell`：统一顶栏、退出和导航。

## 校验

- `npm run build` 必须完成 TypeScript 编译和 Vite 打包。
- 使用浏览器手动验证登录 → 总览 → 地图 → 热点 hover/click → 抽屉 → 详情 → 返回流程。
- 通过 Playwright 截图检查 1440×900 下登录、地图和详情页布局。
